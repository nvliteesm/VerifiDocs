The reference-list table is `reference_entries`, because `references` is a reserved SQL word. |
| 17 Nov 2026 | Events retention (decided by Steven): `events` rows do not expire and have no foreign key to sessions, so the beta metrics survive a 30-day purge. Events hold ids, counts and buckets only, never draft text, quotes or reference text. This is the one exception to "every row expires in 30 days". |
| 17 Nov 2026 | Dev branch (decided by Steven): leave the 7-day expiry as is and recreate the branch when it expires, using the steps in `CLAUDE.md`. |
| 17 Nov 2026 | `AGENTS.md` (decided by Steven): not kept. `agentRules: false` in `next.config.ts` stops `next dev` generating it; `CLAUDE.md` is the single source of agent guidance. |
| 17 Nov 2026 | Dependency added (approved by Steven): `mammoth` (BSD-2, no install scripts of its own) to read .docx drafts. Crossref and OpenAlex use Node's built-in `fetch`, no new package. |
| 17 Nov 2026 | A citation that matches no entry in the reference list, cannot be read, or points at an entry neither Crossref nor OpenAlex knows gets Reference not found (decided by Steven). The reason text says which, so the student can tell "not in your list" from "not found in the services". |
| 17 Nov 2026 | A claim that cites several references is Reference not found if ANY cited reference is not found; otherwise it is checked against those that have a usable PDF, and Can't check only if none does. |
| 17 Nov 2026 | Citation matching: a marker naming one author ("Lee, 2021", "Smith et al., 2021") must match the entry's FIRST author; a marker naming several surnames matches if all appear, in any order. Numeric markers map to list position. |
| 17 Nov 2026 | Reference lookup rules: a candidate matches only if its title matches the entry (80% of title words, at least two) AND its first author's surname appears in the entry. A year more than one off still counts as found but sets `yearMismatch` (preprint mirrors carry other years). "Not found" requires every lookup to have answered; a failed lookup is a retry, never a verdict. A 429 or 503 is retried once after the server's Retry-After wait, capped at 3 seconds. |
| 17 Nov 2026 | Crossref and OpenAlex requests carry only the reference entry's text and a generic User-Agent (`VerifiDocs-portfolio/0.1`), with no contact email, so no personal detail leaves the machine. The cost is that Crossref's public pool has lower rate limits than its polite pool. Decided by Steven: keep it generic and cache each resolved reference per run on `reference_entries` (migration 0003, `reference-cache.ts`) instead of adding an email. Revisit if the beta is still throttled. |
| 17 Nov 2026 | Claim extraction: the model must copy each claim and citation verbatim. Code drops any claim or citation not found in the draft (after the shared normalization), counts the drops, and never turns a dropped citation into "no citation". The draft is passed as delimited data with an instruction to ignore instructions inside it. |
| 17 Nov 2026 | Starting limits (the draft limit was raised to 250,000 characters on 18 Nov, see the scan row below): draft 60,000 characters (longer is rejected, not cut), .docx 5 MB, about 6,000 characters per extraction unit, 40 claims per unit, 200 reference entries. |
| 17 Nov 2026 | Source finding: a student-linked document wins; otherwise the DOI or the resolved title printed in the first three pages of an uploaded PDF, then the title words in the filename (the only clue for a scan). Scanned PDFs are reported as Can't check with a reason. |
| 17 Nov 2026 | Extraction recall (decided by Steven): measured in the eval, not tuned by hand. A live test missed one plain uncited claim ("The central bank raised interest rates by 25 basis points in March."). The eval gets a set of whole drafts with every factual claim labelled, with extraction recall reported next to verdict accuracy and a held-out slice. Until then, extraction misses are an unmeasured risk. |
| 17 Nov 2026 | Next build step (decided by Steven): stage 5, PDF text extraction and all-or-nothing ingest. A PDF text library needs Steven's approval before it is added. |
| 17 Nov 2026 | Dependency added (approved by Steven): `unpdf` 2.x (MIT, 3 MB, no dependencies, no install scripts, from the `unjs` organisation) to read PDF text page by page. Its optional peers (`pdfjs-dist`, `@napi-rs/canvas`) are not installed. It requires Node 24 or newer, which matches the dev machine; whether the free host offers Node 24 is unverified. |
| 17 Nov 2026 | Stage 5 design: the PDF arrives in one request and its bytes are never stored (no file column exists), so there is nothing to delete after ingestion. Normalized page text is saved to `pages` first; the browser then calls an ingest request repeatedly, each chunking, embedding and saving the next 10 pages in one transaction. The document is `ingesting` (invisible to retrieval) until the last batch flips it to `ready` in that same transaction. A failed batch writes nothing and is safe to retry; two overlapping requests cannot double-write. A scan (no text) becomes `no_text` at upload. `abandonDocument` deletes a document with its pages and chunks. |
| 17 Nov 2026 | Stage 5 starting limits: 10 MB per PDF, 300 pages, 10 sources per session, 10 pages per ingest request. Tune after the first beta runs. |
| 17 Nov 2026 | Judge (stage 7): sees only the claim and the retrieved passages, never a model-written reference answer. Passages are labelled P1, P2, ... and the model answers with the label in `chunk_id`; code maps it to the real chunk, because models mistype long ids. The saved page is the chunk's page, not the model's. When unsure between Supported and Partial the judge is told to choose Partial. |
| 17 Nov 2026 | Quote gate (stage 8, hard rule 1): Supported, Partial and Contradicted all require a quote; none, or one that is too short (under 4 words or 20 characters after normalization), or one not found in the retrieved passages, becomes Can't tell at exit stage 8 and no quote is stored. The quote is searched in the passage the judge named first, then in the others (found elsewhere is accepted and flagged `reattributed`). The stored quote is the source's own text. Not in sources and Can't tell never carry a quote. |
| 17 Nov 2026 | Fix this claim: optional, only for Partial and Contradicted. The model sees only the claim and the verified quote. Every number in the suggestion must appear in the quote or in the claim's citation, otherwise no suggestion is made; a suggestion identical to the claim is also dropped. The verdict never depends on it. |
| 17 Nov 2026 | Claim check (stages 3 to 9): at most 3 attempts. A failed lookup or model call returns `retry`; the third failure saves Can't tell with the reason. A claim that already has a verdict is returned without any lookup or model call. The first saved verdict wins, nothing is overwritten, and events are logged once. |
| 17 Nov 2026 | Events (stage 9, hard rule 11): every event has a strict schema in `src/lib/events.ts`, so an unexpected key such as `quote` or `text` is rejected and a string is only allowed as an enumerated value or a short lowercase token. A run is closed, and `run_completed` logged once, only when the run status is `checking` and its last claim gets a verdict; the route sets `checking` after extraction finishes. |
| 17 Nov 2026 | Every Gemini request has a hard deadline, 15 seconds by default (`timeoutMs`), reported as `LlmUnavailableError` and retried by the claim check. Found when a live run stalled for 300 seconds because the adapter had no deadline. |
| 17 Nov 2026 | API routes (all dynamic): `POST /api/runs`, `POST /api/runs/:id/extract`, `GET /api/runs/:id`, `POST /api/sources`, `POST /api/sources/:id/ingest`, `GET /api/sources`, `DELETE /api/sources/:id`, `POST /api/claims/:id/check`, `POST /api/events`. Handlers are plain functions that take their dependencies, so they are tested against the real dev database without a server; the route files are thin wrappers. |
| 17 Nov 2026 | Claim extraction is one request per unit of the draft, tracked in `run_units` (migration 0004). A run is `extracting` until every unit is recorded, then `checking`; a repeated request for a unit changes nothing. When the last unit lands the run is closed at once if every claim already has a verdict or there are no claims (`completeRunIfFinished`, shared with `saveVerdict`). |
| 17 Nov 2026 | Session (hard rule 7): a 256-bit random token in an httpOnly, SameSite=Lax cookie (`vd_session`, 30 days, Secure on https); only its SHA-256 hash is stored. A missing, malformed or unknown cookie starts a fresh empty session and never reveals another. A write whose `Origin` header names another site is refused before anything else happens. Every query is scoped to the session. |
| 17 Nov 2026 | API errors map to short fixed messages. A database that is waking up and a model that is busy both answer 503 with `retry: true` and a `Retry-After`, so the UI can show "waking up" instead of an error. An unexpected error is logged by name and code only and its message is never returned. Path ids that are not UUIDs are a plain 404. |
| 17 Nov 2026 | Browsers may report only seven events through `POST /api/events` (evidence opened, verdict flagged wrong, fix accepted, recheck started, report exported, would-pay answered, feature interest answered), each validated by its strict schema. The server logs every other event itself, so they cannot be forged. |
| 17 Nov 2026 | Starting limits: 20 runs per session, 200 KB per JSON request, 5 MB per .docx, 10 MB per PDF. **Unverified:** serverless hosts may cap the request body well below 10 MB (Vercel's function limit is believed to be about 4.5 MB). Check the chosen host before relying on the PDF limit. |
| 17 Nov 2026 | Database connection: the pooled `DATABASE_URL` with prepared statements off (PgBouncer transaction mode). Verified end to end over real HTTP. Test timeout raised to 30 seconds because database tests cross the internet to Singapore. |
| 17 Nov 2026 | Retrieval ties are broken by upload order and chunk position, never by random id. Found because the same claim got Contradicted, Partial and Not in sources across six live runs: chunk ids are new on every ingest, so an id tie-break reordered the passages and changed the margin of the top 5. After the fix, four live runs agreed. |
| 17 Nov 2026 | Reference lookup has a hard overall deadline of 7 seconds (5 seconds per request, capped by time left, Retry-After waits counted). When it is spent the result is `error` (retry), never `not_found`. Found when one claim check took 21.8 seconds because concurrent lookups of one reference hit Crossref's rate limit and chained retries and searches. |

| 17 Nov 2026 | **Changes the 17 Nov rule above** (decided by Steven after browser testing): a reference that neither Crossref nor OpenAlex knows is no longer Reference not found when an uploaded PDF matches that entry. Found by testing: a Bank Indonesia report is cited in skripsi, is not in those services, and a student who had uploaded its PDF was told the reference "may be made up". The PDF now stands in as the evidence. A match is the filename's words all appearing in the entry, or most distinctive words of the entry printed in the PDF's first 3 pages (`matchEntryToDocuments`, `find-source.ts`). With no match it is still Reference not found, and the reason now says no upload matched. A matching scan gives Can't check. The wording is a heuristic to tune on the eval set. |
| 17 Nov 2026 | A session keeps its latest 20 checks. Creating one more deletes the oldest instead of refusing with 409 (the screen only reopens the latest check, so an older one is unreachable, and there was no way to free a slot). Claims, verdicts, units and reference entries go with the run. A manual "delete my check" is a separate, still open item. |
| 17 Nov 2026 | Rate limits (placeholders to tune from real use): 60 new sessions per address per hour, 600 model-backed requests (extract, check, ingest) per session per hour, 3,000 per address per hour. Counters live in Postgres (`rate_limits`, migration 0005) because in-memory counters do not survive serverless hosting. Keys are a hash of the address or a session id, never text, and expired rows are swept. The address comes from `x-forwarded-for`, which is trustworthy behind Vercel but forgeable with no proxy, so the per-address limits are best effort. |
| 17 Nov 2026 | A reference list of up to 500 entries is accepted (was 200, silently cut). Over the limit is rejected with the count and the limit, never cut: a silent cut made later citations look "not in your reference list". |
| 17 Nov 2026 | The same PDF cannot be added twice to a session: its SHA-256 is kept in `documents.content_hash` (the file itself is still never stored) and a second upload gets 409 `duplicate_source` naming the first. |
| 17 Nov 2026 | The browser checks one claim per distinct citation first and then the rest, so claims that cite the same reference find its online lookup already kept instead of all looking it up at once. Measured: one Crossref lookup took 4.6 s and 12.6 s on repeat, OpenAlex 2.0 s, and lookups run one after the other. Running Crossref and OpenAlex in parallel would cut the wait further; that touches the lookup rules above and is left for a decision. |

| 17 Nov 2026 | "This verdict is wrong" now asks why, from a fixed list of buttons (the quote does not support it, a different page, the source says something else, it misread my claim, I already uploaded this source, something else). No text box: the event carries `verdict` and `reason` only, so Hard Rule 11 holds and nothing the student types is stored. Reasons are offered only where they fit (quote reasons need a quote). Decided by Steven. |
| 17 Nov 2026 | The "would you pay" question is a single Yes / Maybe / No. The Rupiah price buckets are gone, with their odd "Only if it is free" after a Yes, and `would_pay_answered` carries `answer` only. Price is for interviews, not the product. Decided by Steven. |
| 17 Nov 2026 | A student can stop a running check ("Stop checking"). It ends as "Check stopped by you" with the verdicts so far; unchecked claims read "Not checked" and the tally never says everything is supported. Claims already in flight on the server finish. Reloading reopens the same run and continues it, as it does for any interrupted check. |
| 17 Nov 2026 | A student can delete a check now (`DELETE /api/runs/:id`), with a second confirming step. The draft text, claims, verdicts and reference entries go at once; events stay (ids, counts, buckets). The screen only says it is gone after the server confirms, and treats "already gone" (404) as deleted. Source PDFs keep their own Remove. Hard Rule 4 still sets the 30-day limit for anything not deleted sooner. |
| 17 Nov 2026 | Theme colours are written once with CSS `light-dark()` (the old stylesheet repeated the dark palette in a media query and again for the saved override). The computed colours were compared with the old palette in system light, system dark, forced light and forced dark, and all 18 matched. The theme switch follows the system until the student chooses. |
| 17 Nov 2026 | Lint and CI (approved by Steven). `npm run lint` is ESLint with `eslint-config-next` and `eslint-plugin-jsx-a11y` (Next 16 removed `next lint`). typescript-eslint cannot run on TypeScript 7 (no compiler API until 7.1), so `typescript` is an npm alias for `@typescript/typescript6` and `@typescript/native` is an alias for TypeScript 7, per Microsoft's guidance. `npx tsc` is still 7.0. Revisit when TypeScript 7.1 and typescript-eslint support it. Two `react-hooks/set-state-in-effect` findings (reading the saved theme and consent after mount, because the server cannot know them) are suppressed on those lines with the reason written there. CI is `.github/workflows/ci.yml`: typecheck, lint, tests, build, no secrets; the database and live tests skip themselves. |
| 17 Nov 2026 | Component tests use jsdom, `@testing-library/react`, `@testing-library/dom` and `@testing-library/user-event` (dev dependencies, approved by Steven). A test file opts into jsdom with a comment on its first line; the default environment stays node. |
| 17 Nov 2026 | "Try an example": a first-time visitor can load a made-up report (Contoh Statistics Office, Kota Contoh; first page says it is fictional) and a draft written against it, through the normal upload path. It shows a spread of verdicts (supported, contradicted, partly supported, not in the sources, reference not found) and relies on the uploaded-PDF rescue, since the made-up reference is in no online service. No real person, organisation or paper is used. The PDF is rebuilt with `node scripts/make-example-pdf.mjs`. |
| 17 Nov 2026 | Screen design (decided by Steven after a persona audit): text is cut hard (one short line per element, no repeated "meaning" line under a verdict); the draft comes before the sources in the page (right-hand column on wide screens); the blocking privacy wall became a short "Before you start" note with "Got it", and checking, uploading and the example stay locked until it is pressed; the source quote starts open for Contradicted and Partly supported; after a check the intro text is hidden (one screen-reader heading stays) and the pay question is a small line at the bottom. A language switch (English and Bahasa Indonesia) is planned: it follows the browser first, and the AI's reasons and suggested sentences follow the draft's language. |
| 17 Nov 2026 | Retention purge (decided by Steven: "purge on new visits"). `purge_expired()` runs from the API, at most once an hour, when a session starts or is first seen in five minutes (`src/lib/retention.ts`). A counter row in `rate_limits` (`purge:expired`) makes one request per hour do it across server instances, and a failed purge never fails the request. Expired data is therefore removed after the next visit, not at the minute it expires. Replace this with a scheduled job when a host is chosen. |
| 17 Nov 2026 | Forwarded addresses (decided by Steven): `x-forwarded-for` and `x-real-ip` are believed only when `VERCEL=1` or `TRUST_PROXY_HEADERS=1`. Otherwise every caller counts as one address ("unknown"), so a forged header cannot dodge the per-address limits, and they act as site-wide limits. The model limits are still placeholders. |
| 17 Nov 2026 | Security headers (decided by Steven): `nosniff`, `X-Frame-Options: DENY`, `Referrer-Policy: no-referrer` and a `Permissions-Policy` that turns off camera, microphone and location are sent always; production also sends `Strict-Transport-Security` and a Content-Security-Policy; `X-Powered-By` is off. The policy allows inline scripts (`'unsafe-inline'`) because Next.js and the theme script in `layout.tsx` write them, so it does not stop injected scripts. It does stop other sites framing the app, other origins receiving data, plugins and `<base>` tags. A nonce-based policy would make every page render per request. The policy was checked on a production build (`next start`) against the dev database: page, theme, upload and a full check ran with no console errors. |
| 17 Nov 2026 | Model JSON (adapter): a reply that is one complete JSON object or array followed by stray text is accepted (the small model sometimes appends `\n"}`, which had silently dropped the fix for Contradicted claims). Text BEFORE the JSON, such as a code fence, is still rejected. |
| 18 Nov 2026 | Languages: English and Bahasa Indonesia (decided by Steven). An EN / ID switch sits in the header. The screen starts in the saved choice, else the browser's language (Indonesian when it is listed first among ours), else English, and remembers the choice in `localStorage`. No library: text is in `src/lib/i18n/messages.ts`, `en` is the source and `id` must have the same keys and `{placeholders}` (the compiler and a test check it). Indonesian uses "kamu". The fixed reasons the server writes stay English in the database and are turned into the screen's language on screen and in the copied report (`src/lib/i18n/reasons.ts`, built from the English templates so a wording change fails a test). The AI's own text (a verdict's reason, a suggested sentence) follows the language of the claim, not the screen. A new Indonesian example (made-up "Badan Statistik Contoh" report and draft) is loaded when the screen is Indonesian. Not measured: how well the checker judges Bahasa Indonesia drafts (the Bahasa eval claims are still to be written). The Indonesian wording was written by Claude and needs a native reader. |
| 18 Nov 2026 | Judge prompt: the language of the "reason" is named, not left to the model. `src/lib/pipeline/language.ts` counts common function words to tell Indonesian from English in the claim, and the prompt says "written in Indonesian (Bahasa Indonesia)" or "written in English"; if it cannot tell, the old instruction ("in the same language as the claim") stays. Reason: in a live check, 2 of 4 reasons for Indonesian claims came back in English with the old wording. This changes the prompt text the eval baseline will use. |
| 18 Nov 2026 | Bringing a draft in without pasting it (decided by Steven): a Google Docs link (shared as "Anyone with the link"), a PDF, or a .txt file, besides paste and .docx. No browser automation: the server downloads `docs.google.com/document/d/<id>/export?format=txt` (short, no agent browser, no card). The address is built from the document id alone; redirects are followed by hand and only to `docs.google.com` and `doc-*-docstext.googleusercontent.com` (anything else, such as a sign-in page, is "not public"); 8 s timeout, 2 MB cap, `text/plain` required, 30 imports per session per hour. `POST /api/import` returns the text and saves nothing; the student sees it in the draft box and can edit it before checking. The link is never stored or logged (event `draft_imported` has only the source and a length bucket). A .txt file is read in the browser. A PDF draft is read on the server, its lines are rebuilt into paragraphs, and a scan is refused. Private documents are not supported (no accounts, hard rule 7). A "Publish to web" link (`/d/e/2PACX.../pub`) is refused with its own message: its text export does not exist (404), though the page itself carries the text, so it could be read later. Checked on real public documents on 18 Nov 2026: the export redirects (307) to a `docstext.googleusercontent.com` host; the text has a byte-order mark and `\r\n` line endings; lists come out as `* item`; a table is one cell per line starting with a tab (columns are lost, so a warning is shown when many lines start with a tab); footnotes are inline `[n]` markers with the notes after a line of underscores (the block and the markers are removed, with a warning, because a left-over `[1]` would be read as reference 1; footnote-style citing is therefore not checked); 12 rapid exports from one machine were all answered 200. Not verified: documents with several tabs (no public example was found; the text box shows exactly what was read, so a missing tab is visible), and rate limits from a hosting provider's addresses (test after deploying). |
| 18 Nov 2026 | Claim extraction, a bug fix that does not change the 17 Nov rule above: the small model sometimes writes the word `"null"` (or `None`, `N/A`) as a claim's citation instead of a JSON null. It was treated as a citation that is not in the draft, so the claim was dropped (24 of 25 claims on a real draft with no visible citations). Those words now mean "no citation". A real citation that is missing from the draft is still dropped and never turned into "no citation". |
| 18 Nov 2026 | Scan first, then check (decided by Steven, after he found that a long document pasted from a link hit the old 60,000-character limit). A check now has two steps. The scan reads the whole draft for claims (`POST /api/runs`, then one `extract` request per slice of about 6,000 characters) and, when the last slice is read, gives the claims that need no lookup their verdict at once, in a few bulk statements (`src/lib/pipeline/scan.ts`, using `matchCitation` from `prelude.ts`, the same code the check uses): No citation, an unreadable citation, and Reference not found for a citation that is not in the reference list (with the usual "no reference list was added" reason when none was given). The cited claims that are in the list wait, with no verdict, in the new client phase `scanned`. The screen then shows a summary (found, without a citation, not in your list, cited and ready) and one button, "Check N cited claims", which runs the existing per-claim check (Crossref, source search, judge) for the claims still waiting. A run with nothing left to check closes at the scan. Reopening a check whose cited claims are still waiting lands on the scan, not in the middle of a check. The draft limit is 250,000 characters (about 100 pages; the request body limit is 1.1 MB), still enforced by the server. Measured on 18 Nov with the free Gemini key, 218,000 characters: 62 slices, 127 seconds, all answered 200, 823 claims. The size limit is a quota and time limit, not a technical one. After a link, PDF or .txt is read, the screen shows a short card (what was read, how many references were found, a preview, "Edit the text") instead of a text box, and one press of "Scan my draft" scans it. The first button is now "Scan my draft". Not done: the result list is flat (647 cards on the long run), so grouping or paging would help; "Check again with my sources" still creates a new run and reads the draft again. |
| 18 Nov 2026 | One session per browser, found on the long scan: a page's first two requests (for example the sources list, which React runs twice in development) each started a session and set a cookie, and the later cookie won. A check created in the first session then answered Not found for every request after it. ## Why some things are out

- **Humanizer and AI detection:** they contradict the self-check positioning, detectors are unreliable, and they would attract users who do not use the checker. Demand can be probed with a question in the beta's "would you pay?" prompt.
- **Firebase:** Cloud Functions need the Blaze plan, and Blaze needs a payment method (Firebase pricing page, checked 17 Nov). Cloud Storage is listed with a no-cost Spark quota on that page, although a community source says it now needs Blaze, so that point is unresolved. Firestore also has no built-in keyword search. Neon was chosen mainly because it keeps Postgres, pgvector and full-text search with no card.
- **Python backend:** the legacy app was FastAPI and Supabase. The rebuild is one TypeScript codebase. The Python RAG code is a reference only (tag `legacy-rag-chat`).
