## Confirmed bugs (seen in the browser)

Ordered by severity. File paths and lines are as of commit `6f96d88`.

1. **HIGH: a failed check shows only "Something went wrong." and loses the draft.**
   - Repro: make `POST /api/runs` fail (patch fetch to 500), paste a draft, click "Check my claims".
   - Result: Results panel shows one alert and only "Start a new check". The draft is gone, with no cause and no retry.
   - Cause: `DraftPanel` holds its text in local state ([DraftPanel.tsx:17-21](src/components/DraftPanel.tsx#L17-L21)) and is unmounted when the phase leaves idle ([VerifierApp.tsx:142](src/components/VerifierApp.tsx#L142)). "Check again" only shows when `phase === "done"` ([VerifierApp.tsx:153](src/components/VerifierApp.tsx#L153)).
   - Fix direction: keep draft state in `VerifierApp` or a hook, or show "Try again" using `lastInput` on error. Show a specific error reason. Add a test.

2. **HIGH: the evidence disclosure has no visible arrow.**
   - "What your source says (page N)" looks like a static label. `summary` is `display: flex`, which removes the marker ([globals.css:614-621](src/app/globals.css#L614-L621)).
   - This is the main trust feature of the product.
   - Also fix the hint "Open a claim to see the quote from your source" ([ResultsView.tsx:167](src/components/ResultsView.tsx#L167)). It points at the wrong thing.
   - Fix direction: add an explicit chevron or `::before` marker that rotates when `[open]`. Check it in both themes and against reduced motion.

3. **MEDIUM: "This verdict is wrong" resets when the filter changes.**
   - `flagged` is local state in `ClaimCard` ([ResultsView.tsx:33](src/components/ResultsView.tsx#L33)). The card unmounts on filter change, so a user can flag again and inflate `verdict_flagged_wrong`.
   - `copied` has the same problem ([ResultsView.tsx:34](src/components/ResultsView.tsx#L34)).
   - Fix direction: keep a set of flagged claim ids in `ResultsView` or the verifier state.

4. **MEDIUM: "Check again with my sources" is missing after a reload.**
   - `lastInput` is a ref that is not restored on resume ([VerifierApp.tsx:46](src/components/VerifierApp.tsx#L46)). A reopened check shows only "Copy report" and "Start a new check".
   - Fix direction: restore the input, or offer the recheck from the stored run, without storing draft text where Hard Rule 4 and 11 would be broken. Decide with Steven if it needs the draft persisted.

5. **MEDIUM: the headline counter is misleading while checking.** It shows "0 of 3 claims need attention." before any claim has finished ([ResultsView.tsx:163-166](src/components/ResultsView.tsx#L163-L166)). Show it only when the run is done, or show progress instead.

6. **MEDIUM: no focus move or announcement when results arrive.**
   - After a check finishes, `document.activeElement` is `<body>`.
   - The only live region is the progress line, which unmounts when finished ([ResultsView.tsx:146-151](src/components/ResultsView.tsx#L146-L151)).
   - Fix direction: move focus to the Results heading (tabIndex -1) or announce the tally through a persistent `role="status"` region.

7. **MEDIUM: the empty reference list gives a misleading error.**
   - With the reference list left empty, cited claims return "Reference not found: may be mistyped or made up" and mention Crossref.
   - The real cause is the empty list, and the field is labelled "optional" ([DraftPanel.tsx:87-89](src/components/DraftPanel.tsx#L87-L89)).
   - Fix direction: when the list is empty, say so in the verdict reason, and make the field label honest about when it is needed. Find the reason string under `src/lib/` (not located during the review).

8. **LOW: "Step 2 of 2" appears on both the draft panel and the results panel** ([ResultsView.tsx:142](src/components/ResultsView.tsx#L142), [DraftPanel.tsx:44](src/components/DraftPanel.tsx#L44)). Rename the results label.

9. **LOW: "Report copied" never reverts** to "Copy report" ([VerifierApp.tsx:168](src/components/VerifierApp.tsx#L168)). Reset after a few seconds and announce it through a live region.

10. **LOW: on mobile the results sit below the whole sources panel** ([VerifierApp.tsx:136-141](src/components/VerifierApp.tsx#L136-L141)). After a check the user must scroll past sources. Consider placing results first on narrow screens once a run exists.

11. **LOW: favicon 404** is the only console error. There is no icon in `src/app/`.

## Product and production gaps (decisions for Steven)

- No "delete my check now". The only DELETE route is `src/app/api/sources/[id]/route.ts`. Retention is 30 days with no manual delete, and this is a privacy-sensitive product.
- The "would you pay" survey wording and price buckets are placeholders awaiting approval. "Only if it is free" is offered after a "Yes".
- "This verdict is wrong" only sends an analytics event. The user cannot say why, and the verdict does not change.
- No CI (no `.github/workflows`), no rate limiting on the API routes, no linter (so no `jsx-a11y`), no host chosen, and no eval harness. Production audit estimate was about 62/100 ("Risky").
- The Neon `dev` branch expires on 24 Nov 2026. Re-create it as described in `CLAUDE.md`.
- No sample or demo data, so a first-time visitor cannot see a result without their own PDFs.
