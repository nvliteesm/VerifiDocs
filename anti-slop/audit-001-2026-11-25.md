# antislop audit 001, 25 Nov 2026

Mode: AFTER (chosen by Steven this session). Scope: the redesign of the start screen, the run strip, the workspace (draft page, review card, claim list, sources drawer, phone sheet) and the done screen, built from the Claude Design canvas "VerifiDocs UI Redesign".

Design Read: self-check for final-year students, set like a proofed page of paper, in a quiet-paper style, dial ENERGY 2 / RHYTHM 2 / MOTION 2.

Nothing below has been changed. Pick the numbers you want fixed.

Priority follows the rule tier: Hard Gate = HIGH, Purpose-Gate = MEDIUM, Quality Locks = LOW.

## HIGH (Hard Gate)

1. **R-25, contrast.** `--ink-3` (#6b727a) on the desk colour (#f3f4f1) measures 4.41:1, under the 4.5:1 AA bar. It is used for the small mono labels (`.pane-title`, `.sub-title`, `.remedy-title`, `.ba-label`), the done rows in the claim list and the not-yet-ticked `[1]` markers, many of which sit on the desk rather than on white paper. Dark mode passes (5.29 to 5.90). Fix: darken `--ink-3` in light mode to about #646b73.
2. **R-32, focus after the last fix.** When the final issue is handled, the done screen replaces the draft, and the focus-the-toast logic points at a line that is now `display: none`, so keyboard focus falls to the page top. Fix: move focus to the done headline when the done screen appears (only if focus has been lost), as the old design did for its done line.
3. **R-32, drawer focus.** The sources drawer takes focus on open and closes on Escape, but it does not keep Tab inside while open, so the draft behind it can still be tabbed into. Fix: make the content behind the drawer inert while it is open.
4. **R-35, verification gaps.** Clicked through in a real browser (Chrome via Playwright, real Gemini): start screen, scan, live check, review card, Apply fix and Ignore, the done screen, "Back to the draft", the 375px sheet, the dark toggle. Not clicked in a browser: the sources drawer (covered by a unit test only), keyboard-only use, Bahasa Indonesia, the 375px start screen and done screen, `prefers-reduced-motion`, a failed check and an empty check. These need a pass before this ships.
5. **R-03, phone.** The claim list is hidden under 1024px (as it was before), so on a phone the only ways between claims are the underlines and the prev/next buttons, and the verdict filters are only inside the drawer. Not a regression, but the reference's phone screens do not show a list either, so confirm that is intended.

## MEDIUM (Purpose-Gate)

6. **R-07, dotted background.** The desk behind everything is a dot grid. It comes from the reference. Purpose written: it makes the draft read as a page lying on a desk. R-37 asks you to keep it or drop it. Keep / drop?
7. **R-06, tracked mono labels.** `[ CHECK BEFORE YOU SEND ]`, `[ YOUR RECEIPT ]`, `[ WHAT CHANGED ]`, and BEFORE / AFTER use small mono type with wide tracking. They are the bracket motif of the reference, but R-06 names this pattern. I kept them sentence case where the reference allowed it. Keep / drop?
8. **R-23, logo.** The wordmark now uses the bracket-and-tick mark from the reference in place of the rounded-square tick. The reference supplied it, but R-23 asks for confirmation before a logo changes. Confirm.
9. **R-19, motion.** Eight entrance animations exist: screen fade, card slide, list rise, toast drop, tick pop, block grow, receipt print, sentence sweep. Each has a purpose (state change or progress), except the receipt's 1.2 degree tilt, which is decoration from the reference. Keep / drop the tilt?
10. **R-29, palette.** One blue plus eight verdict colours (green, amber, orange, purple, rose, two greys). Purpose: each verdict needs its own colour, icon and underline, and the blue is the single action colour. Within the rule only because verdicts are status colours, so it is listed for your sign-off.

## LOW (Quality Locks)

11. **C-4 / R-27, empty states.** The ready card during checking, the drawer, and the done screen have no dedicated empty or error variants (for example: a check that stops with zero issues and zero supported). The old inline messages still cover the common ones.
12. **R-16 / R-31, Bahasa Indonesia copy.** New ID strings ("Pastikan setiap sitasi sudah tepat.", "Struk cekmu", "Aman dikirim.") were written by me, not read by a native speaker. This was already an open item in the project notes.
13. **R-14, three identical step cards.** The three start steps share one layout. They are real inputs, not marketing steps, so I judge this fine, but it is the one place the rule could be read against it.
14. **Dead strings.** `ws.pane.*`, `ws.panes`, and `start.get.*` message keys are no longer used by any screen. Remove them, or keep for later.
15. **Docs.** `DESIGN.md` (colours, fonts, layout) and `docs/decisions.md` still describe the previous design, so the "approved UI spec" the project instructions point to is now out of date. A decisions row and a note at the top of `DESIGN.md` are needed.

## Gate result

Hard Gate: items 1 to 5 open. No em dash, no fabricated numbers (the receipt shows only real counts, and the reference's "~20s left" was left out on purpose), no dead controls found in the click-through, no fake testimonials.
